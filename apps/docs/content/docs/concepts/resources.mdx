A **Resource type** is a business data shape, such as customer, ticket, invoice, or asset. A
**Record** is one instance of that type. You create Resource types by describing them in chat; the
assistant writes JSON Schema into the [Soul](/docs/concepts/soul), and TulipFarm reconciles storage
and UI from that schema.

## Schema in the Soul, Records in Postgres

Resource type definitions live at `soul/resources/{name}/schema.yml`. Records live in per-type
Postgres tables. Reconciliation creates or updates the storage shape from the schema and runs live,
so a new type is ready without restarting.

Here is the kind of read-only artifact the assistant writes underneath:

```yaml title="soul/resources/customer/schema.yml"
type: object
properties:
  name:
    type: string
  email:
    type: string
    format: email
required:
  - name
```

Every create, replace, patch, and delete is validated server-side. Validation failures return a
JSON Pointer `path`, so both the UI and Agents can point to the field that failed.

## Generated UI

The web app generates list, detail, create, edit, and schema views from the Resource type schema.
Strings become text inputs, numbers become numeric inputs, booleans become checkboxes, enums become
selects, `date` and `date-time` formats become date controls, and arrays or objects become JSON
text areas. `x-links` fields render as searchable comboboxes, and `x-immutable` locks a field on
edit.

This is why Resource types are more than tables: the schema is also the contract that drives a
zero-code UI and the Agent tools.

## Links and extensions

`x-links` declares a relationship to another Resource type. TulipFarm verifies linked Records exist
on write, rejects invented ids, and shows unresolved links when a target has been soft-deleted.

Common data-shaping extensions include `x-normalize` for canonical forms, `x-computed` for derived
values, and `x-id-strategy` for human-friendly references such as `TICK-123`. The system UUID
remains the stable primary id.

## Resource hooks

A Resource type can also include `hooks.ts`. Hooks run in the `@tulipfarm/sandbox` isolate and are
managed by `PUT`, `GET`, and `DELETE /api/v1/resource-types/{name}/hooks`. They cover logic that is
awkward to express declaratively, while static analysis blocks banned patterns before the hook is
stored.

Use [Define a resource type](/docs/guides/define-a-resource-type) to build a type and
[Work with records](/docs/guides/work-with-records) to use Records.
