title: Knowledge
description: Spaces and pages that Agents search, cite, revise, link, and graph.

**Knowledge** is the searchable wiki that Agents and people use for policies, procedures, reference
notes, and explanations. It is organized into **spaces** and **pages**, stored in Postgres, and
indexed for retrieval.

## Spaces and pages

A space is a wiki-like area. A page is markdown at a path inside a space. Pages have revisions,
backlinks, tags, a per-space graph, and a progressive navigation tree. Agents can create spaces,
write pages, navigate a space, fetch a page by path, inspect backlinks, and query Knowledge.

Use [Use the knowledge wiki](/docs/guides/use-the-knowledge-wiki) for the editing flow.

## Links, mentions, and graph

Page links are tracked so each page can show what links to it. The graph view shows pages as nodes
and links as edges, including faded stubs for links that leave the space. Mention pickers expose
Knowledge pages so chat can cite or target the right page.

## Search and citation

`POST /api/v1/knowledge/search` searches Knowledge. When an embedding model is configured, pages are
chunked, embedded, and searched with pgvector. Without embeddings, TulipFarm logs that embeddings
are not configured and falls back to lexical search rather than failing.

Agents use `query_knowledge` and `cite_sources` to answer with evidence. Use
[Cite knowledge in chat](/docs/guides/cite-knowledge-in-chat) for the user-facing flow.

## Operations

Admin APIs can re-index one page, a whole space, or the corpus; backfill missing embeddings; and
inspect index health. These are operational controls, not authoring steps. Knowledge content itself
is created through the UI, API, or Agent tools.
