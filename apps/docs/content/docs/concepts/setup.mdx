---
title: First-run setup and boot modes
description: How TulipFarm opens the setup wizard or seeds a fresh instance from environment variables.
---

A fresh TulipFarm instance needs an admin user, a business profile, and usually an LLM provider
before it is useful. Setup can happen through the web wizard or through environment-driven headless
bootstrap.

## Wizard mode

Wizard mode is the default when no users exist and no headless admin seed is present. The web app
redirects to `/setup`, where the operator creates the first admin, records the business name and
description in `soul.yaml`, optionally configures an LLM provider, and optionally configures Soul git
backup.

The business profile becomes static business context in the system prompt. It is not working
[memory](/docs/concepts/memory). LLM provider credentials are stored as [secrets](/docs/concepts/secrets),
and Soul backup syncs immediately when configured.

`GET /api/v1/setup/status` remains available so the web app can decide whether setup is still open.
Once setup is complete, `setupComplete: true` is written to `soul.yaml`.

## Headless mode

Headless bootstrap is for deployments where configuration is injected before the first boot.
`ADMIN_EMAIL` and `ADMIN_PASSWORD` seed the first admin when no users exist. Supplying `LLM_API_KEY`
completes the full headless seed by storing the default provider key as well. In production,
admin credentials without `LLM_API_KEY` are refused so the instance does not start half-configured.

`BUSINESS_NAME` and related business environment values can seed the Soul profile. The bootstrap is
idempotent: once any user exists, it does not create another admin.

## Recovery shape

The persistent setup marker is in the Soul, but the database still matters. If `soul.yaml` is
restored from an old backup without `setupComplete` and users already exist, the instance treats
setup as complete rather than reopening first-admin creation. If the database is lost, users,
Records, Knowledge, Runs, secrets, and identity are lost even if the Soul survives.

See [Back up and restore](/docs/guides/back-up-and-restore) for operational guidance.
