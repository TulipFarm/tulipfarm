TulipFarm is a self-hosted, AI-native business operating system. You operate it through
[chat](/docs/concepts/chat): ask for everyday work, ask for new business objects, or ask for an
Agent to take over a focused job. Underneath that simple surface is a deliberate split.

**Soul** is the git-backed definition store. It lives at `~/.tulipfarm/soul` by default and holds
Resource type schemas, Agents, Skills, Routines, Integrations, Surface components, `soul.yaml`,
`guardrails.yaml`, and `skills-lock.json`. Model configuration is the `llm` block in `soul.yaml`.
Soul writes commit immediately and
reconcile live, so a newly built Resource type or Agent is available without restarting.

**The datastore** is PostgreSQL 17 with pgvector. It holds Records, Knowledge spaces and pages,
chats, Runs and Run events, Approvals, memory, secrets, audit, identity, and queues. It is the
business state; the Soul is the business definition.

That split is why TulipFarm can be both agent-built and operationally durable: Agents write the
Soul when they build the system, but every turn, routine execution, integration delivery, and wait
is persisted as a [Run](/docs/concepts/runs) in the datastore.
