---
title: Bundled integrations
description: How bundled integrations appear in the catalog, verify provider access, and limit the actions available to agents.
---

An integration is a connected third party. Bundled integrations arrive with every instance, ready
to connect. You do not install them. You connect one by giving TulipFarm the credentials and setup
values its provider requires.

None of them are connected by default. Nothing leaves your instance until you connect one.

## Find what is bundled

Open **Integrations** to see the catalog shipped by your release. Each card describes the provider
and opens its current setup steps. The catalog is the source of truth because providers and their
available operations can change between releases.

Some integrations expose provider actions to agents. Others also receive provider events, publish
provider content into knowledge, or let people talk to agents from another service. The detail page
shows the capabilities of that exact package.

## Connect one

The setup screen walks you through the steps declared by the integration. A step can ask for
non-secret settings, encrypted credentials, or an OAuth sign-in.

When a bundled package declares provider verification, the Connection remains unavailable until
TulipFarm saves successful verification evidence. **Retry verification** repeats that declared
check. An unavailable provider leaves the result incomplete; it is not proof that the credentials
work. A provider rejection requires corrected or reconnected credentials.

Credentials are stored encrypted in the secrets store. They are not written to the soul or shown
to an agent.

## What agents can do

Every integration is defined by a manifest. The manifest declares **egress**, what agents may do to
the provider, and **ingress**, what the provider may send to TulipFarm.

Each provider action becomes a separate tool with a fixed destination, input shape, output shape,
and effect such as read, create, update, or delete. An agent cannot choose an undeclared provider
address or call an operation that is absent from the manifest. Actions that require approval still
pause for approval.

## Add a provider that is missing

Ask in chat to build an integration from the provider's public documentation. TulipFarm reviews
and tests the exact package before asking you to approve publication. Published packages appear in
the same catalog as bundled integrations.

Existing reviewed packages can also be installed from **Integrations → Install from source**.
Before installation, the screen shows the resolved ref, exact digest, capabilities, effects,
destinations, authorization requirements, and incoming data. See
[Connect an integration](/docs/administration/connect-an-integration#install-from-a-source).
