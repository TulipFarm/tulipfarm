An integration connects TulipFarm to an external service. Open **Integrations** to see the
options available in your release.

## MCP servers

Third-party agent tools use MCP, the Model Context Protocol. A server can offer tools,
information called resources, and templates called prompts. Review the capabilities you
want to allow rather than treating a catalog listing as permission to use everything.

The catalog is setup guidance, not a guarantee that every server feature works with
TulipFarm. Discovery does not enable capabilities, and changing a server's configuration
requires a new review.

## Supported server connections

Remote servers must offer Streamable HTTP over HTTPS. A website address or an older
standalone SSE endpoint is not a substitute for the server's MCP endpoint.

{/* tf-claim kind=path-exists value="packages/schema/src/mcp.ts" */}

The supported protocol revisions are `2025-11-25`, `2025-06-18`, and `2025-03-26`.
Unsupported revisions are refused. This is not a claim of support for a 2026 protocol revision
or every optional MCP feature. Server requests for sampling, roots, or elicitation are not
enabled.

Local servers use an isolated standard-input/output connection. They need a container image
pinned by digest, an executable inside that image, and an explicit list of outbound hosts.
They do not inherit the host environment or run directly on the host. The container backend
shipped for development is not a production isolation guarantee. Production uses the
Kata Containers runtime, `io.containerd.kata.v2`, and refuses to fall back to an ordinary
container. The host must have a working Docker and Kata installation with the required
virtualization support; installing TulipFarm alone does not install that host runtime.

See the upstream [Kata Docker setup guide](https://github.com/kata-containers/kata-containers/blob/main/docs/how-to/how-to-use-kata-with-docker.md)
for supported host and runtime requirements. If the host cannot provide this isolation,
use a remote HTTPS MCP server instead.

Token entry and browser sign-in use the secure account controls in **Integrations**. Do not
put credentials in a server address, chat message, or agent instructions. Successful sign-in
or discovery is not proof that a provider action, reply, or Knowledge sync has been tested.

## Knowledge sync

Connecting an MCP server does not automatically make it a Knowledge source. Knowledge sync
currently supports only the pinned local GitHub server profile and a personal token account.
Choose **Set up GitHub Knowledge (local)** in the GitHub catalog entry to prefill that
profile. The separate **Set up GitHub** option uses the remote server.
Its reviewed, read-only `get_me` and `get_file_contents` tools must be available without a
per-call approval. Other server builds, hosted GitHub, Slack, Drive, and Notion are not
supported Knowledge profiles.

{/* tf-claim kind=path-exists value="apps/api/src/integrations/accounts/knowledge.ts" */}

Synced pages remain read-only and private to the account owner. Reading a saved copy still
requires a fresh successful source access check. Losing access or disconnecting removes the
synced copy without deleting separately authored notes.

## Native chat channels

Slack and GitHub channels ship with TulipFarm. They receive events and deliver replies.
Connecting a channel is separate from connecting an MCP server for agent tools.
