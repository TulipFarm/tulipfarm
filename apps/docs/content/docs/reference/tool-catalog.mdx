A **tool** is one callable action an agent asks TulipFarm to run, such as reading a record, writing a
page, starting a routine. Every instance builds the same set of built-in tools at startup, and this
page is generated from that set, so it cannot drift from what your instance offers.

Appearing here is not permission. Every call is checked again against the agent's own limits and
the caller's access, and a tool an agent may not use is never offered to it. See
[what agents can do](/docs/using-tulipfarm/what-agents-can-do) for how that reads from the outside,
and [roles and permissions](/docs/reference/roles-and-permissions) for how the checking works.

**Changes things** marks a tool that writes something. Every other tool only looks.

Two groups are deliberately missing. Tools for a connected app arrive with the app, so they are
listed per provider under [bundled integrations](/docs/reference/bundled-integrations). Tools that
draw a reply on screen are explained in [surfaces](/docs/using-tulipfarm/surfaces).

## Business data

Reading and changing the records your resource types describe.

| Tool | Changes things | What it does |
| --- | --- | --- |
| `record_create` | Yes | Create a new record of the given resource type. |
| `record_delete` | Yes | Soft-delete a record. |
| `record_find_similar` | No | Find records of a resource type whose given field is textually similar to the given text (fuzzy match, not exact). |
| `record_get` | No | Get a single record by id. |
| `record_list` | No | List records of a resource type. |
| `record_search` | No | Search records of a resource type by field values (JSONB containment match). |
| `record_update` | Yes | Merge-update a record. |

## The knowledge base

Searching, reading and writing the cited pages agents answer from.

| Tool | Changes things | What it does |
| --- | --- | --- |
| `cite_sources` | No | Declare the knowledge pages you used to answer. |
| `create_knowledge_page` | Yes | Author a new knowledge page (markdown). |
| `create_space` | Yes | Create an Open Knowledge Format space, a navigable, cross-linked tree of pages (a wiki). |
| `get_backlinks` | No | List the pages that link to a page (its inbound 'linked from' references, same- or cross-space). |
| `get_page` | No | Fetch a knowledge page's full content by its pageId. |
| `get_page_by_path` | No | Fetch one exact knowledge page by its space id and path (e.g. 'policies/refunds'), a direct lookup with no search/ranking. |
| `get_space_graph` | No | Get a space's cross-link graph (its page nodes and the links between them) to understand how a space's pages relate. |
| `list_governance_pages` | No | List the business's standing policies, Knowledge pages the operator marked as always applying. |
| `list_spaces` | No | List the available knowledge spaces (id, name, description). |
| `navigate_space` | No | Walk a knowledge space one directory at a time (progressive disclosure). |
| `query_knowledge` | No | Search the shared knowledge base by meaning (vector) with a lexical fallback. |
| `write_page` | Yes | Author or update one Open Knowledge Format page in a space. |

## What an agent remembers about you

The single document an agent carries between chats with you.

| Tool | Changes things | What it does |
| --- | --- | --- |
| `get_memory` | No | Read everything durable you have recorded about this user: who they are, how they want you to reply, and standing rules they have given you. |
| `update_memory` | Yes | Edit the user's durable memory document, carried across every future chat with this user. |

## Saved values

Short-lived values an agent stores for itself. Not business data, and not memory.

| Tool | Changes things | What it does |
| --- | --- | --- |
| `kv_delete` | Yes | Delete an entry by (namespace, key) from your key-value store. |
| `kv_get` | No | Read a JSON value by (namespace, key) from your key-value store. |
| `kv_list` | No | List all live entries in a namespace of your key-value store. |
| `kv_set` | Yes | Store a JSON value under (namespace, key) in your key-value store. |

| --- | --- | --- |

## Work handed back to a person

Raising, and closing, work the runtime needs a human to do.

| Tool | Changes things | What it does |
| --- | --- | --- |
| `task_close` | Yes | Close a Task by its dedupeKey, used by the creating Agent to signal the underlying gap is resolved. |
| `task_create` | Yes | Create a Task, a unit of work the runtime asks a human to do (never a user-facing todo item; that is a Resource Type instead). |

## Moving around the app

Reading and moving the screen you are on. Only ever offered in the browser.

| Tool | Changes things | What it does |
| --- | --- | --- |
| `get_client_context` | No | Read what the user is currently looking at in the app: the current route and page title. |
| `invoke_action` | No | Invoke a named client-side action the current page registered (the page decides what each action does). |
| `navigate_to` | No | Navigate the user to an internal app route (must start with '/'). |
| `prefill_form` | No | Pre-fill the form the user currently has open with proposed values (matched by field name) for them to review and confirm. |

This page covers what ships with TulipFarm. Your instance also holds whatever integrations you have
connected, so it is the only complete answer. **Operate → Business → People & access** shows that
live list, grouped into the same areas, with the tool names behind each entry.
