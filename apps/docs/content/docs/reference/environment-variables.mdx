TulipFarm reads configuration from the process environment. Source checkouts usually load `.env.local`; self-hosted installs write `/opt/tulipfarm/.env` for Docker Compose.

Most people arrive here holding one variable name and one question: **am I allowed to change this?** Every variable below names the zone that answers it.

| Zone | Meaning |
| --- | --- |
| Set these | Normal configuration. Change them to suit your deployment. |
| Installer sets these | Overridable, but a wrong value gives you a broken or non-standard install. |
| Never set these | Internal plumbing. Setting them by hand breaks things. |

## Required boot configuration

| Variable | Zone | Required | Default | What it does | If set wrong |
| --- | --- | --- | --- | --- | --- |
| `DATABASE_URL` | Set these | Yes | - | PostgreSQL connection string. Must start with postgres:// or postgresql://. | Without it the process cannot start. Pointed at the wrong database, migrations run against data that was never TulipFarm's. |
| `ENCRYPTION_KEY` (secret) | Set these | Yes outside managed data-dir boot | Generate: `openssl rand -base64 32` | 32-byte base64 key-encryption key for every stored Secret. | A fresh key against a database that already holds encrypted Secrets refuses to boot, by design, rather than orphaning them. |
| `JWT_SECRET` (secret) | Set these | Yes outside managed data-dir boot | Generate: `openssl rand -base64 32` | 32-byte base64 signing secret for auth and session surfaces. | Changing it invalidates every existing session. |
| `WEBHOOK_SIGNING_SECRET` (secret) | Set these | Yes outside managed data-dir boot | Generate: `openssl rand -base64 32` | 32-byte base64 secret for webhook signature verification. | Changing it makes every already-registered provider webhook fail verification. |
| `SOUL_PATH` | Set these | Yes, unless SOUL_ROOT is set | - | Absolute path to the live soul git checkout. | Mutually exclusive with SOUL_ROOT. Setting neither leaves the instance with no configuration to load. |
| `SOUL_ROOT` | Set these | Yes, unless SOUL_PATH is set | - | Root for per-business soul checkouts, resolved as &lt;root&gt;/&lt;businessId&gt;/soul. | Mutually exclusive with SOUL_PATH. |

| `WEB_DIST` | Installer sets | No | - | Directory of built web assets for the API to serve in combined image mode. | Wrong here and the API serves no UI while still answering on its API routes. |
| `INTERNAL_API_URL` | Installer sets | Yes for worker processes | - | Base URL workers use for service-only internal API calls. | Without it workers cannot reach the API, so Runs are claimed and never progress. |

## Workers and service credentials

The API can mint worker credentials into `TF_DATA_DIR`. An environment value always wins; the generated file is only a fallback for container installs that share the data volume.

| Variable | Zone | Required | Default | What it does | If set wrong |
| --- | --- | --- | --- | --- | --- |
| `TF_DATA_DIR` | Installer sets | No | /data when that directory exists | Stores generated secrets.env, worker.env, integration-worker.env, and bucket.env. | This is the durable path that holds the encryption key. Pointing it at ephemeral storage loses every stored Secret on the next restart. |
| `WORKER_API_CREDENTIAL` (secret) | Installer sets | Yes unless read from the data directory | - | Service credential for the durable Run worker. | Without it the worker cannot authenticate, so Runs are never executed and Chat Turns hang mid-stream. |
| `INTEGRATION_WORKER_API_CREDENTIAL` (secret) | Installer sets | Yes unless read from the data directory | - | Service credential for the integration worker. | Without it inbound provider events are accepted and never processed. |
| `WORKER_PORT` | Set these | No | 4020 | Worker health probe port. | Health probes and the readiness gate have nowhere to answer. |
| `WORKER_OWNER` | Never set | No | &lt;hostname&gt;:&lt;pid&gt; | Lease owner recorded on claimed Runs. | Two workers sharing an owner string can reclaim each other's live Runs. |
| `WORKER_RUN_POLL_MS` | Set these | No | 1000 | Durable Run dispatch poll interval. | Raising it adds latency to every Chat Turn; lowering it adds database load. |
| `WORKER_WAIT_SWEEP_MS` | Set these | No | 5000 | Wait timer sweep interval. | Raising it delays every timer-based Routine step. |
| `WORKER_OUTBOX_POLL_MS` | Set these | No | 1000 | Event outbox delivery poll interval. | Raising it delays outbound delivery of every emitted event. |
| `WORKER_BATCH_SIZE` | Set these | No | 25 | Maximum Runs claimed per dispatch batch. | Raising it increases throughput and the number of Runs lost to a single crash. |
| `WORKER_LEASE_MS` | Set these | No | 60000 | Run lease duration. | Must exceed WORKER_RUN_POLL_MS or the worker refuses to start. |
| `WORKER_RUN_MAX_LIFETIME_MS` | Set these | No | 900000 | Longest a single Run keeps renewing its lease before the worker abandons it for reclaim. | Must exceed WORKER_LEASE_MS or the worker refuses to start. |
| `WORKER_DRAIN_TIMEOUT_MS` | Set these | No | 15000 | Worker shutdown drain budget. | Set below the platform's termination grace period, or in-flight Runs are killed rather than drained. |
| `WORKER_MAINTENANCE` | Installer sets | No | false | Enables singleton maintenance consumers on one worker replica. | Enabling it on more than one replica runs singleton work concurrently. |
| `INTEGRATION_WORKER_PORT` | Set these | No | 4030 | Integration-worker health probe port. | A port collision presents as a worker that will not start. |
| `INTEGRATION_WORKER_DRAIN_TIMEOUT_MS` | Set these | No | 15000 | Integration-worker shutdown drain budget. | Set below the platform's termination grace period, or in-flight delivery is killed. |

## Sessions, Secrets, and limits

Model configuration can also reach an environment variable directly, through an `env://<NAME>` reference. That escape hatch is not a variable this contract can enumerate. The name is chosen when the model is configured, and it must already be set at that moment.

| Variable | Zone | Required | Default | What it does | If set wrong |
| --- | --- | --- | --- | --- | --- |
| `SESSION_TTL_SECONDS` | Set these | No | 604800 | Session cookie lifetime in seconds. | Lowering it signs people out sooner; raising it widens the window a stolen cookie stays usable. |
| `ENCRYPTION_KEY_PREVIOUS` (secret) | Set these | No | - | Previous 32-byte base64 key, read during key rotation. | Removing it before rotation completes leaves anything still encrypted under the old key undecryptable. |
| `API_TOKEN_PEPPER` (secret) | Set these | No | Generate: `openssl rand -base64 32` | 32-byte base64 HMAC key for hashing personal API tokens. | Changing it invalidates every existing personal API token at once. |
| `RECOVERY_KEY` (secret) | Set these | No | - | Offline recovery key, consumed by the key recovery command. | Command-line use only. Leaving it in a running process's environment defeats the point of an offline key. |
| `HOOKS_DISABLED` | Never set | No | - | Set true to skip Resource hook execution. | Disables every side effect Records are supposed to trigger. A debugging switch, not configuration. |
| `AUTHZ_MODE` | Set these | No | enforcing | Set to the exact value shadow to rehearse an authorization change. The engine still evaluates, but every route falls back to its declared admin or member check. | Shadow mode can refuse nobody, so leaving it on means a policy that looks applied is not. Every disagreement is logged as authz.divergence; run in shadow until that log is quiet, then unset it. |
| `AUTHZ_MODEL_GATE` | Set these | No | shadow | Set to the exact value enforcing to make model-access decisions refuse rather than only report. | Defaults to shadow so an upgrade cannot lock a deployment out of its own models. Enforcing it before the divergence log is quiet denies real callers. |

## File storage

Unset, files land on disk under `TF_DATA_DIR`, which is correct for development and wrong for anything with more than one replica or a container that restarts. The Compose stack points these at its bundled bucket service; see [where uploaded and generated files go](/docs/self-hosting/docker-compose#where-uploaded-and-generated-files-go).

| Variable | Zone | Required | Default | What it does | If set wrong |
| --- | --- | --- | --- | --- | --- |
| `BLOB_STORE` | Set these | No | Inferred from S3_BUCKET or the Azure variables | filesystem, s3 or azure. Exists only to force the choice; naming a bucket, or an Azure account or connection string, already selects the driver. | Setting a driver without its credentials refuses to boot rather than silently storing files on a disk that vanishes. |
| `S3_BUCKET` | Set these | S3 only | - | Bucket that holds every File's bytes. | Naming it selects the S3 driver, so a typo here silently changes which driver runs. |
| `S3_REGION` | Set these | No | us-east-1 | Signing region. Every S3-compatible provider signs with one, even single-region ones. | A wrong region fails at request-signing time, which reads as an auth error rather than a configuration one. |
| `S3_ENDPOINT` | Set these | No | Amazon's own host | Provider endpoint. Omit it for Amazon S3 itself. | Setting it also turns on path-style addressing by default, because a custom endpoint is usually MinIO, Ceph, or a host reached by IP. |
| `S3_ACCESS_KEY_ID` (secret) | Set these | S3 only | - | Access key for the bucket. | Provisioned automatically when the bundled bucket service is on. |
| `S3_SECRET_ACCESS_KEY` (secret) | Set these | S3 only | - | Secret key for the bucket. | Provisioned automatically when the bundled bucket service is on. |
| `S3_FORCE_PATH_STYLE` | Set these | No | On whenever S3_ENDPOINT is set | Use path-style bucket addressing. | MinIO, Ceph, and any host reached by IP cannot serve virtual-hosted bucket names. |
| `S3_PREFIX` | Set these | No | - | Key prefix, for sharing one bucket with something else. | Changing it on a populated bucket hides every File already stored under the old prefix. |
| `AZURE_STORAGE_CONTAINER` | Set these | Azure only | - | Blob container that holds every File's bytes. | Naming it, with a credential, selects the Azure driver; a typo silently changes which container the instance reads and writes. |
| `AZURE_STORAGE_CONNECTION_STRING` (secret) | Set these | Azure, unless AZURE_STORAGE_ACCOUNT and AZURE_STORAGE_KEY are set | - | Full Azure Storage connection string. The one credential shape that also carries a sovereign-cloud or Azurite endpoint. | Naming it selects the Azure driver. Present, it wins over account-and-key. |
| `AZURE_STORAGE_ACCOUNT` | Set these | Azure, unless AZURE_STORAGE_CONNECTION_STRING is set | - | Storage account name, paired with AZURE_STORAGE_KEY, for the public Azure cloud. | Naming it selects the Azure driver. Without AZURE_STORAGE_KEY the instance refuses to boot rather than starting without a usable credential. |
| `AZURE_STORAGE_KEY` (secret) | Set these | Azure, unless AZURE_STORAGE_CONNECTION_STRING is set | - | Account key for AZURE_STORAGE_ACCOUNT. | The shared key that authorises every read, write and same-account copy; wrong here reads as an auth error at boot, not a configuration one. |
| `BUCKET_ADMIN_URL` | Installer sets | No | http://bucket:3903 in Compose | Admin API of the bundled bucket service. The API provisions the bucket and its access key there on first boot. | Set it empty to use an external provider instead; left pointing at a bundled service that is not running, first boot fails to provision storage. |

## Database and knowledge tuning

| Variable | Zone | Required | Default | What it does | If set wrong |
| --- | --- | --- | --- | --- | --- |
| `DATABASE_URL_MIGRATIONS` (secret) | Set these | No | - | Separate connection string used only to run migrations, for deployments where the runtime role cannot alter schema. | Unset, migrations run as the runtime role, which then needs schema privileges it otherwise would not. |
| `PG_POOL_MAX` | Set these | No | - | Maximum PostgreSQL pool connections per process. | Every replica opens its own pool, so the effective total is this times the replica count, against the server's own connection limit. |
| `PG_CONNECTION_TIMEOUT_MS` | Set these | No | - | How long to wait for a pool connection before failing. | Raising it turns pool exhaustion into slow requests rather than fast errors. |
| `PG_STATEMENT_TIMEOUT_MS` | Set these | No | - | Server-side statement timeout. | Set too low, long migrations and large retrieval queries are cancelled mid-flight. |
| `PG_IDLE_TIMEOUT_MS` | Set these | No | - | How long an idle pool connection is kept before it is closed. | Set too high, idle connections hold server slots; too low, every burst pays to reopen them. |
| `PG_IDLE_IN_TRANSACTION_TIMEOUT_MS` | Set these | No | - | Server-side timeout for a session left idle inside an open transaction. 0 disables it, keeping the server default. | A transaction left open holds its locks; without this a stuck client can block others indefinitely. |
| `KNOWLEDGE_TRGM_FALLBACK` | Set these | No | on | Enables pg_trgm typo tolerance for lexical page search unless set to 0 or false. | Disabling it makes misspelled searches return nothing rather than near matches. |
| `KNOWLEDGE_RERANK` | Never set | No | - | Opts into the wired rerank seam. | The enabled stage is an honest not-implemented stub, so turning it on changes nothing today. |
| `KNOWLEDGE_GRAPHRAG` | Never set | No | - | Graph-augmented retrieval switch. | Internal retrieval tuning; changing it alters what agents cite without any product-level control. |
| `KNOWLEDGE_GRAPH_EXPAND` | Never set | No | - | Graph expansion switch for retrieval candidates. | Internal retrieval tuning; widening candidates costs latency on every retrieval. |
| `KNOWLEDGE_AUTHORED_PAGES_IN_RETRIEVAL` | Never set | No | - | Whether authored pages join retrieval candidates. | Internal retrieval tuning; changing it alters what agents cite. |
