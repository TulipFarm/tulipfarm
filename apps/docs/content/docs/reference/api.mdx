TulipFarm serves the public API under the real prefix `/api/v1`. On your own instance, the live
OpenAPI document is available at `/api/v1/openapi.json`.

Use a concrete host for your deployment, for example `https://tulipfarm.example/api/v1` or
`http://localhost:4010/api/v1` in local development.

## Authentication

Browsers authenticate with the `tf_sid` session cookie. Mutating browser requests must also echo the
`csrf_token` cookie in the `x-csrf-token` header. Login, logout, invite preview, and invite accept
are the pre-session exceptions.

Scripts can use personal API tokens as bearer credentials. Tokens are created under
`POST /api/v1/auth/tokens`, have the `tulip_` prefix, and are shown only once. See
[Issue an API token](/docs/guides/issue-an-api-token).

```bash
curl -X POST https://tulipfarm.example/api/v1/auth/tokens \
  -H "Content-Type: application/json" \
  -H "Cookie: tf_sid=<session>; csrf_token=<csrf>" \
  -H "x-csrf-token: <csrf>" \
  -d '{"name":"reporting-script"}'

curl https://tulipfarm.example/api/v1/resources/customers \
  -H "Authorization: Bearer tulip_<token>"
```

## Errors

Most error responses are JSON objects with an `error` string. Validation errors may include a
`path` JSON Pointer so clients can attach the message to a field.

| Status | Meaning |
| --- | --- |
| `401` | No valid session cookie, personal API token, or API-client credential was accepted. |
| `403` | The principal is authenticated but not allowed to perform the action. |
| `404` | The requested route or record was not found, or is not visible to this principal. |
| `409` | Concurrency or idempotency conflict, such as a stale write or replayed chat turn. |
| `422` | Request validation failed. Resource validation includes a JSON Pointer `path` when available. |
