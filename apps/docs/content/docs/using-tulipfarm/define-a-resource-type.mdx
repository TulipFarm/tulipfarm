This guide creates a [Resource type](/docs/using-tulipfarm/resources) by chatting with the
assistant. Resource types live in the soul; records live in PostgreSQL.

## Outcome

At the end, the new type appears under **Resources**, with generated list, detail, create,
and edit screens based on its schema.

## Ask the assistant

Open **Chat** and describe the type you want:

```prompt
Create a ticket Resource type. It should have a subject, a status that is either
open or closed, a priority of low, medium, or high, and a customer it belongs to.
Auto-number each ticket as TICK-1, TICK-2, and link the customer to our existing
customer Resource type.
```

The assistant loads `resource-forge`, asks for any missing details, writes the schema to
the soul, commits it, and reconciles it live. There is no restart.

<Callout type="info">
Links can only point at resource types that exist. If you ask for several related types,
the assistant creates them in dependency order.
</Callout>

## Verify the generated UI

<Steps>
  <Step>
    Open **Resources**.
  </Step>
  <Step>
    Select the new type. The record list is generated from the schema.
  </Step>
  <Step>
    Choose **New**. The create form is also generated from the schema: strings become text
    inputs, numbers become number fields, booleans become checkboxes, enums become selects,
    dates become date pickers, arrays and objects become JSON textareas, and links become
    searchable comboboxes.
  </Step>
  <Step>
    Save an invalid value, such as a status outside the enum, to confirm the server
    rejects it. Validation is server-authoritative and returns field paths for the UI to
    display; the browser form is only a helper.
  </Step>
</Steps>
