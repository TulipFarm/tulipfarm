This guide creates a custom [agent](/docs/using-tulipfarm/agents) by chatting with the default
assistant. Agents are soul artifacts; `agent-forge` writes their `AGENT.md` files for you.

## Outcome

At the end, the agent appears in **agents** and can be selected in chat.

## Ask the assistant

Open **Chat** and describe the job, boundaries, and autonomy you want:

```prompt
Create a support Agent that answers customer questions from Knowledge pages,
checks customer Records when needed, and files a ticket when follow-up is
required. It should ask for Approval before making customer-visible changes.
```

The assistant loads `agent-forge`, asks follow-up questions, writes `AGENT.md` in the
soul, commits it, and reconciles live.

## Choose autonomy

When the forge asks, choose the level that matches the risk:

- `full` acts without pausing.
- `supervised` acts and surfaces what it did.
- `approval-required` pauses before gated actions.
- `manual` is driven step by step.

## State the hard limits

Anything you phrase as "must never" becomes an enforced restriction, not just wording in the
agent's instructions. Say it plainly and the forge writes it into the agent's frontmatter:

```prompt
Create a reporting agent that may only list and view records of any resource
type, and must never create, update, or delete a record.
```

The server then refuses those tool calls even if the agent is talked into making one, and the agent
cannot hand the work to a less restricted agent instead. Ask the forge to read the restriction back
to you before it commits, so you can correct it. See
[Agents](/docs/using-tulipfarm/agents#tools-and-current-limits).

## Reuse or replace an existing name

If an agent with that name already exists, the forge stops before it writes and asks you once
which one you mean. Answer in chat:

```prompt
Leave the existing agent unchanged.
```

Say "update the existing agent" instead and the forge rewrites that agent rather than adding a
second one with the same name. Either answer ends the question. The forge does not ask again.

## Verify and use it

<Steps>
  <Step>
    Open **Agents** and select the new agent.
  </Step>
  <Step>
    Review its purpose and governance card.
  </Step>
  <Step>
    Start a chat with that agent from the agent picker, or mention it from the composer.
  </Step>
</Steps>

To change it later, ask the assistant to edit the agent. You do not edit `AGENT.md` by
hand in normal use.
