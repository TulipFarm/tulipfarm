**Knowledge** is a wiki that both you and your agents can read. It holds the things your business
knows, policies, procedures, prices, how you handle a refund, what your opening hours are.

The point is not storage. The point is that when an agent answers a question, it can answer *from
your knowledge* and tell you which page it used.

## Spaces and pages

Knowledge is organised the way you would expect:

- A **space** is an area, like a folder: "Support", "HR", "Pricing".
- A **page** is a single document inside a space.

Every page keeps its old versions, so you can see what changed and when. Pages can link to each
other, and each page shows what links back to it, so you can see what depends on the thing you are
about to change.

There is also a map view showing pages as dots and links as lines between them: useful for
spotting a page nobody references, or a page everything depends on.

## Answers come with sources

When you ask a question, an agent searches knowledge and cites the pages it used. You can open the
cited page and check it.

That is the difference between an assistant that sounds confident and one you can actually verify.
If the answer is wrong, you fix the page, and every future answer is fixed too.

<Callout>
Search works whether or not your instance is set up for meaning-based search. With it, an agent
finds a page about "time off" when you asked about "holiday". Without it, search still works by
matching words. It never simply fails.
</Callout>

## Keeping it true

Knowledge is only as good as what is in it. Because pages are versioned and linked, the usual
failure (a policy page that quietly went stale two years ago) is visible rather than invisible.

Agents can write pages too, so a thing an agent learns once can become a page everyone reads.
