Open **Integrations** to see connections to external services. An integration gives TulipFarm
a defined way to use an external service; it does not give every agent unrestricted access.

## Agent tools use MCP

MCP, the Model Context Protocol, lets a server offer tools, resources, and prompts.
A **tool** performs an action. A **resource** returns information. A **prompt** supplies a
template. MCP resources are not TulipFarm records.

Discovering a capability does not authorize it. TulipFarm keeps a reviewed selection, and
checks that a capability still matches that review before using it. A changed server
configuration requires a new review.

The server's own description is not a permission grant. Calling a tool still passes through
TulipFarm's access and approval controls.

## Definitions and credentials stay separate

The soul is TulipFarm's versioned configuration store. It holds non-secret definitions, not
provider passwords or tokens. Credentials belong in the encrypted secrets store, not in
agent instructions or chat messages.

An integration account connects one provider identity to an integration. A **personal
account** belongs to one user. A **shared account** is explicitly granted for use by users,
teams, or a routine, which is a scheduled or triggered automation.

Private chat uses your selected personal account, or your personal default when no account
has been selected yet. It never silently switches to a shared account. Using a shared
account in chat requires both permission and your explicit selection and consent. Changing
your default does not replace an account already selected for an existing chat.

Scheduled work uses an explicitly approved account and the routine configuration that was
approved with it. A shared account is not a universal token that every agent may use.
Changing the account or the routine's approved instructions or output destinations can
require new approval. Personal credentials cannot be used to send data into shared
Slack or GitHub conversations.

Disconnecting or revoking access does not cause a fallback to another identity.

## Chat channels are separate

Native Slack and GitHub channels receive provider events and deliver agent replies.
They do not expose a second way to add third-party agent tools.

Slack users link their Slack identity to a TulipFarm account. GitHub event delivery uses the
GitHub App installed for your deployment. These channel paths keep their own provider
verification and delivery controls.
