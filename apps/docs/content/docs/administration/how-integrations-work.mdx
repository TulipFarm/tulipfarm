---
title: Integrations
description: The bundled integrations, what they enable, and current limits.
---

Integrations connect TulipFarm to external systems. Seven ship bundled: **GitHub**, **Slack**,
**Telegram**, **Notion**, **Confluence**, **Google Drive**, and **Google Docs**. All appear in the
integrations UI and store their configuration through the soul and secrets store.

You are not limited to those. An integration is a data file — a manifest describing how to
connect and which provider API calls agents may make — so one can be installed from any git
repository, and nothing that installs runs code. See
[Connect an integration](/docs/administration/connect-an-integration#install-from-a-git-repository).

## GitHub

The GitHub integration is installed as a GitHub App scoped to the organizations and repositories you
choose. It lets agents list repositories, read and search issues and pull requests, comment, label,
assign, close, create pull requests, review, merge, read check runs, push content, and read or list
repository content.

GitHub also powers soul backup to a GitHub repository through the soul repo routes. The integration
renders through `@tulipfarm/surface-github` for comments and Check runs.

Use [Connect GitHub](/docs/administration/connect-github) for setup.

## Slack

The Slack integration lets users talk to TulipFarm agents from Slack through Socket Mode: direct
messages, channel messages, and app mentions. Slack routes can bind a channel, or a default catch-
all, to an agent so different channels reach different business specialists.

Slack users must link their Slack account to a TulipFarm user through the single-use channel-link
flow. Approval prompts can be answered in Slack, and surface interactions resolve back into the same
TulipFarm interaction contract used by the web app. Slack knowledge sync keeps a durable per-channel
cursor.

Use [Connect Slack](/docs/administration/connect-slack) for setup.

## Telegram

The Telegram integration lets your team talk to agents from Telegram — direct messages, group
chats, and forum topics. Each forum topic and each reply chain is its own chat, so several
conversations can run in one group without merging.

It ships no provider-specific code. The manifest names the API calls to publish and describes how
an inbound update becomes a chat, including how TulipFarm registers the webhook with Telegram and
generates the secret that proves a delivery is genuine.

Use [Connect Telegram](/docs/administration/connect-telegram) for setup.

## Notion

The Notion integration lets agents search the workspace, read page properties and body content,
create and update pages, append content, and read and query databases. Access is per-page: the
integration reaches only what you explicitly share with it in Notion.

It ships no provider-specific code. The manifest names the operations to publish and the runtime
compiles them into tools — the same path any integration installed from a git repository takes.

Use [Connect Notion](/docs/administration/connect-notion) for setup.

## Confluence, Google Drive, and Google Docs

These three are read-only. Agents can search Confluence and read a page, search Drive and read a
file's details, and read a Google Doc's body. There are no write tools: the scopes they ask for are
read scopes, and a write tool against a read token would report an edit that never happened.

All three also index into knowledge, and that path preserves per-user access rather than flattening
it — a page you cannot see in Confluence is not one an agent will cite to you. Access is resolved
through external identity mappings, so an unmapped account grants nothing. Link-sharing in Drive is
not treated as everyone.

## Current limits

Per-Agent tool restriction is not yet available. Once an integration is connected, its eligible
tools are broadly available to agents on turns with the right authority. Do not rely on per-Agent
integration allowlists today.
