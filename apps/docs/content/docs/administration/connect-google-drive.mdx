---
title: Connect Google Drive
description: Connect Google Drive so agents can search files, read metadata, and index Drive files into knowledge with Google permissions.
---

Connecting Google Drive lets your agents search your files and read their details. It is
read-only — agents cannot change or delete anything in Drive.

Add a Google Workspace ID as well and TulipFarm indexes your Drive files into
[knowledge](/docs/using-tulipfarm/knowledge), so agents can cite them in chat. Google's own
permissions are respected: nobody sees a file through TulipFarm that they could not open in
Drive.

For the shared catalog flow, see [Connect an integration](/docs/administration/connect-an-integration).
This page covers only the Google fields.

## Outcome

At the end, Google Drive shows as connected. Agents can search files by name, type, owner, or
modification date, then read each file's metadata, owners, and link.

Drive tools do not read file bodies. For a Google Doc's body, connect
[Google Docs](/docs/administration/connect-google-docs) too.

## Create Google access

<Steps>
  <Step>
    In [Google Cloud Console](https://console.cloud.google.com/apis/credentials), open the project
    serving this deployment and enable the Google Drive API.
  </Step>
  <Step>
    Create an OAuth client. To cover a whole workspace, create a service account with domain-wide
    delegation instead; that is a Google account type that can act across the workspace.
  </Step>
  <Step>
    Grant the `drive.metadata.readonly` and `drive.readonly` scopes. The permissions access is what
    lets knowledge preserve Google access instead of flattening it.
  </Step>
  <Step>
    Copy a current access token. You will paste it into TulipFarm in the next step.
  </Step>
</Steps>

## Connect Google Drive

<Steps>
  <Step>
    Open **Integrations → google-drive**.
  </Step>
  <Step>
    Paste your workspace or customer identifier into **Google Workspace ID**
    (`GOOGLE_WORKSPACE_ID`) only if you want Drive files indexed into knowledge. The agent tools
    work without it.
  </Step>
  <Step>
    Paste the token into **Google Drive OAuth Access Token** (`GOOGLE_DRIVE_ACCESS_TOKEN`) and save.
    It is encrypted in secrets, the encrypted store for provider credentials.
  </Step>
</Steps>

## Verify

Return to **integrations** and confirm Google Drive shows connected. Then ask in chat:

```prompt
Find Google Drive files named roadmap and show me their owners and links.
```

## If Drive files do not appear

- **The search is empty** — check that the token covers the files you expect and has both read
  scopes from the setup step.
- **Knowledge has no Drive pages** — check that **Google Workspace ID** is filled in. It is only
  needed for knowledge indexing.
- **You need a document body** — connect Google Docs. Google Drive tools return metadata, not file
  content.
