---
title: Connect an integration
description: Choose an MCP server or a native chat channel, review what it exposes, and keep credentials separate from agent instructions.
---

Open **Integrations** to configure an integration, a connection to an external service.
Third-party agent tools use MCP, the protocol that lets TulipFarm ask an external server to
perform a specific action or return information.

## Choose a server

Use a server offered by the provider or one your organization operates. Check its destination,
sign-in requirements, and available capabilities before connecting it. Appearing in a catalog
does not give a server access to your data or authorize its tools.

Provider API documentation and OpenAPI files cannot be imported as agent tools. A provider
without a suitable MCP server is not available through that route.

## Save the server

Select **Add MCP server**, then enter an **Integration ID** and **Display name**. The ID stays
in links and cannot be changed after creation.

Choose the **Server transport**:

- **Remote HTTPS URL** asks for the provider's **Remote MCP URL**, not its website address.
  Do not put tokens in the URL.
- **Local isolated server** asks for a **Pinned container image**, an **Executable path**
  inside that container, and any arguments. Set **Allowed outbound hosts** to the hostnames
  the server needs. An empty list denies outbound network access.

Select **Add server**. New servers start disabled. Local servers require an isolation
backend that your deployment supports; they never fall back to running directly on the host.

## Connect an account

Choose the server's authentication method before discovery: no authentication, token entry,
or browser sign-in. For a local token-based server, declare the credential environment
variables its provider requires, such as `GITHUB_PERSONAL_ACCESS_TOKEN`. Enter their values
only in the account controls, never in the server arguments.

Under **Accounts**, select **Connect another account** and give it an **Account label**.
A personal account uses your provider identity. A shared account uses a separate identity
that can be granted to other users, teams, or scheduled automations. Shared accounts are
available only when the server allows them; they are not an automatic fallback.

For token authentication, enter the requested credentials in the secure fields. For browser
sign-in, follow the provider's authorization page. A server that needs no authentication
does not need an account.

If the provider requires an existing OAuth app, select **Use an existing OAuth app** and
enter its client ID, authentication method, and any required client secret. Select
**Save OAuth account**, then use **Copy callback URL** on the account card. Register that
exact URL with the provider before selecting **Connect account**. If the server's
authentication configuration changes, create a new account rather than reusing an old
app's credentials against the changed destination.

## Review capabilities

Open **Approved capabilities** and select **Discover capabilities**. Discovery lists what
the server offers; it does not enable those capabilities. Select the specific tools, resources,
and prompts you want to allow, then choose **Save approved capabilities**. A resource is
information returned by the server. A prompt is a template the server provides.

When using a shared account for setup, explicitly select it in the setup account picker
before discovery. The same account is used when saving the review. This selection permits
setup and review, not personal use of the shared account or shared content previews.

Under **Server**, select **Edit server**, turn on **Enable this MCP server**, and select
**Save server** when you are ready to use it. Enabling the server does not grant account
access or approve additional capabilities.

Changing the server configuration clears its previous capability review. Review the new
capabilities before using that configuration. A server cannot silently add tools to an existing
review.

## Set up GitHub Knowledge

For read-only copies of GitHub files in Knowledge, choose **Set up GitHub Knowledge (local)**
from the GitHub catalog entry. It prefills the supported local server rather than the remote
GitHub server. The host still needs the isolation support described in the
[integration catalog](/docs/reference/bundled-integrations#supported-server-connections).

Save the server, connect a personal token account, and review `get_me` and `get_file_contents`
as read-only tools without per-call approval. Enable the server, then open
**Manage Knowledge sync** to select the files to sync. The preset does not approve tools
or grant account access for you. Shared accounts and the remote GitHub server are not
supported for Knowledge sync.

## Connect a chat channel

Slack and GitHub chat channels have separate setup. Their event delivery and agent replies do
not depend on an MCP server.

- [Connect Slack](/docs/administration/connect-slack)
- [Connect GitHub](/docs/administration/connect-github)

Use [How integrations work](/docs/administration/how-integrations-work) to understand the
difference between an agent tool and a chat channel.
