---
title: Connect an integration
description: Connect an account from another service with a simple setup flow, keep personal and shared access separate, and adjust limits when needed.
---

Open **Integrations** and choose the service you want agents to use. An integration lets
agents work with that service through an account you connect and access you approve.

## Choose an integration

Select **Connect** beside a provider, or **Manage** to manage an account you have connected.
A panel opens from the right without leaving the catalog. It shows the provider and the
account details you need.
Open **Setup help** for the provider's instructions and requirements.
For a listed provider, TulipFarm supplies its name and connection settings.
You do not need to name the integration or your first account.

Follow the account instructions in the panel:

- **Access token** uses a secret key supplied by the provider. Paste it into the secure field
  and select **Connect**.
- **Browser sign-in** uses the provider's authorization flow after you select **Connect**.
  Some providers require an app to be registered first.

Only sign-in methods supported by that provider are offered. Opening or cancelling the panel
does not save an integration or account.

On first setup, connecting checks the account, saves the provider's current capabilities and
enables the integration. You do not need to discover or select each Tool. A Tool is an action
an agent can call. The initial setup requires approval for every Tool call.

Existing custom limits stay unchanged. A provider cannot silently add new capabilities to the
saved access. Use **Advanced settings** only when you want to change those limits.

## Add another provider

Select **Add integration**, enter a **Name**, and paste the **Integration URL** supplied by
the provider. This must be its MCP address, not its website or API documentation. MCP is the
protocol TulipFarm uses to discover and call a provider's tools. Never put an access token
in the URL.

Choose the provider's sign-in method, then select **Continue** to save the setup and connect
an account. **No sign-in** is only for services that require no credentials.

**Advanced settings** contains hosting details and the automatically chosen **Integration ID**.
The ID stays in links and cannot be changed after creation.

Use **Where it runs → On your infrastructure** only when the required isolated runtime is ready.
The image, executable, arguments and permitted network destinations belong here, not in agent
instructions. For token-based local integrations, enter only the **Required secret names**;
their values belong to the account. An empty outbound-host list denies network access.

## Connect an account

Follow the provider's sign-in instructions.
The account name is filled in for you; change it only if you need to distinguish accounts.
If an account is already connected, **Add another account** creates a separate connection with a
different suggested name. It does not replace the first account's token or switch an existing Chat.
A personal account uses your provider identity. A shared account uses a separate identity
that can be granted to other users, teams, or scheduled automations. Shared accounts are
available only when the integration allows them; they are not an automatic fallback.

For an access token, enter it in the secure field and select **Connect**.
For browser sign-in, select **Connect** and follow the provider's authorization
page. An integration that needs no sign-in does not need an account.

If the provider requires an existing OAuth app, select **Use an existing OAuth app** and
enter its client ID, authentication method, and any required client secret. Select
**Connect**, then use **Copy callback URL** in the saved account's setup. Register that
exact URL with the provider before continuing sign-in. If the integration's
sign-in settings change, create a new account rather than reusing an old
app's credentials against the changed destination.

## Replace an account's token

Open **Manage** for the integration. If several accounts exist, use **Account to manage** to
choose the one you mean. Accounts with the same name show when they were added so you can tell
them apart.

Choose **Replace token**, enter the new value, then choose **Save replacement credentials**.
This updates that same account rather than creating another. The replacement is checked before
the account is shown as connected. Previous consent and access grants must be reviewed again.

The **Manage** link beside a credential in **Secrets** opens its exact account.
Existing Chats keep their selected account; they do not silently switch to a newer one.

## Recover an unfinished connection

An error can leave an account saved with setup still incomplete. Return to that account rather
than adding another one. If the account is already connected, select **Finish connecting**.
You do not need to enter the token again just to finish access setup.

An older setup with empty access settings may offer **Use standard access and connect**.
This explicitly replaces that empty policy with the provider's current capabilities and the
standard approval defaults. Ordinary connection does not reset existing custom limits.

If the screen asks you to correct credentials, enter the token in its recovery form. TulipFarm
uses the same account; it never reads the saved token back into the form. An incomplete setup
does not, by itself, mean the provider rejected your token.

For browser sign-in, finish the authorization for that account. If an existing OAuth app needs
a callback URL, register the exact URL shown before continuing.

Follow the saved setup's retry action if checking access or publishing the configuration failed.
An account can be connected while its saved settings allow no actions or content. The panel
shows this separately from **Ready to use**. If standard access is not offered, select
**Edit allowed access** to review and explicitly save changes; reconnecting does not reset limits.
If setup found no capabilities, check the account's permissions with the provider before
reviewing available access.

## Adjust access limits

This is optional. Open **Advanced settings** to inspect or restrict the saved access.
Detailed controls cover Tools, resources and prompts. A resource is information returned by the
provider. A prompt is a template the provider supplies.

Use the advanced discovery and review controls to change the allowed items. Discovery alone
does not approve newly offered capabilities. Save the review explicitly when you want to
change access; connecting another account does not replace your custom choices.

When using a shared account for setup, explicitly select it in the setup account picker
before checking available access. The same account is used when saving the review. This selection permits
setup and review, not personal use of the shared account or shared content previews.

## Keep personal and shared access separate

Basic setup does not grant anyone a shared account or choose an account for a Chat.
Each person connects their own account unless shared access has been explicitly granted.
Connecting a personal account cannot change the instance's integration policy without
configuration authority.

Open **Integration settings** only when you need to change the setup. Changing these settings
can invalidate saved access. Review affected capabilities in **Advanced settings** before
using the new configuration. Disabling an integration and disconnecting an account remain
separate actions.

## Set up GitHub Knowledge

For read-only copies of GitHub files in Knowledge, open the GitHub panel, expand
**Optional Knowledge sync**, and choose **Set up GitHub Knowledge (local)**.
It prefills the supported local setup rather than the hosted GitHub integration.
The host still needs the isolation support described in the
[integration catalog](/docs/reference/bundled-integrations#supported-server-connections).

Continue with the prefilled setup and connect a personal token account. In **Advanced settings**,
review `get_me` and `get_file_contents` as read-only tools without per-call approval, then open
**Manage Knowledge sync** to select the files to sync. This sync needs those explicit read-only
settings; the basic approval-required defaults are not sufficient. Shared accounts and the
remote GitHub server are not supported for Knowledge sync.

## Connect a chat channel

Use **Messages and events** on the Integrations page for Slack and GitHub channel setup.
Their event delivery and agent replies do
not depend on an MCP server.

- [Connect Slack](/docs/administration/connect-slack)
- [Connect GitHub](/docs/administration/connect-github)

Use [How integrations work](/docs/administration/how-integrations-work) to understand the
difference between an agent tool and a chat channel.
