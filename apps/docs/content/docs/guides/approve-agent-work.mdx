This guide uses the [Inbox](/docs/concepts/approvals) to decide work that needs a human.
A Run can pause on an Approval and resume after the decision is recorded.

## Outcome

At the end, you can approve or deny a waiting item and know where the paused Run resumes.

## Open the Inbox

<Steps>
  <Step>
    Open **Inbox**.
  </Step>
  <Step>
    Review each item kind: Approval, human task, form wait, or access request.
  </Step>
  <Step>
    Read the title, risk, status, intent digest, Guardrail revision, target, destination,
    fields, expiry, and four-eyes decision count.
  </Step>
</Steps>

## Decide an Approval

For an Approval, choose **Approve** or **Deny**. TulipFarm records the server-authorized
decision against the persisted Approval binding; the browser cannot replace the intent,
target, destination, or Guardrail revision.

When a chat turn or Routine State parks on an Approval, the owning Run waits. After the
required decision is recorded, the same Run resumes from that wait. A denial returns to
the Run as a denial so the Agent or Routine can handle it.

<Callout type="warn">
Approve only the action shown. If the target or destination is not what you expected,
deny it and ask for a corrected turn.
</Callout>

## Approve from Slack

If the waiting Run originated from Slack, TulipFarm can post an Approve/Deny prompt back
to Slack. Clicking it resolves through TulipFarm's internal Channel link flow so the
decision is attributed to the linked TulipFarm user.

## Verify

Open the related **Run**. Its waits should show the Approval decision, and the Run should
continue, fail, or finish according to the Agent or Routine logic.
