---
title: Issue an API token
description: Create a tulip_-prefixed personal bearer token for API access.
---

This guide creates a personal API token for programmatic access to your TulipFarm
instance. Tokens are bearer credentials, are prefixed with `tulip_`, and are shown once.

## Outcome

At the end, you have a token you can send as a bearer credential without using a
browser session or CSRF header.

## Log in and capture a session

Use your own host, for example `https://tulipfarm.example`:

```bash
curl -c ./tf-cookies.txt -X POST https://tulipfarm.example/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@example.com","password":"your-password"}'
```

Cookie-authenticated writes require a CSRF header matching the `csrf_token` cookie:

```bash
CSRF=$(grep csrf_token ./tf-cookies.txt | awk '{print $NF}')
```

## Create the token

```bash
curl -b ./tf-cookies.txt -X POST https://tulipfarm.example/api/v1/auth/tokens \
  -H "Content-Type: application/json" \
  -H "x-csrf-token: $CSRF" \
  -d '{"name":"billing-sync"}'
```

The response includes the raw token once:

```json
{ "token": "tulip_...", "name": "billing-sync" }
```

<Callout type="warn">
Copy the `tulip_` token immediately. TulipFarm stores only a hash, so it cannot display
the raw value again.
</Callout>

## Use the token

```bash
curl https://tulipfarm.example/api/v1/auth/tokens \
  -H "Authorization: Bearer <your-tulip-token>"
```

Bearer-authenticated requests do not need cookies or a CSRF header.

## List and revoke tokens

```bash
curl -b ./tf-cookies.txt https://tulipfarm.example/api/v1/auth/tokens
```

```bash
curl -b ./tf-cookies.txt -X DELETE \
  -H "x-csrf-token: $CSRF" \
  https://tulipfarm.example/api/v1/auth/tokens/<id>
```
