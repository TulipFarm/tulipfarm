---
title: Work with records
description: Create, find, edit, and delete Records through chat or generated forms.
---

This guide works with Records of an existing [Resource type](/docs/concepts/resources).
If the type does not exist yet, [define it first](/docs/guides/define-a-resource-type).

## Outcome

At the end, you can use either chat or the generated Resources UI to manage Records, with
the API enforcing the Resource type's schema on every write.

## Ask in chat

For most day-to-day work, ask the assistant:

```prompt
Add a customer named Ada Lovelace with email ada@example.com. Then find all open
tickets for that customer and mark ticket TICK-3 as closed.
```

The assistant can read, create, update, delete, and search Records directly. It shows the
result in chat and uses the same server validation as the UI.

## Use the generated UI

<Steps>
  <Step>
    Open **Resources** and select a Resource type.
  </Step>
  <Step>
    Review the list. Columns are generated from the schema.
  </Step>
  <Step>
    Choose **New** to create a Record. Required fields are marked and field controls come
    from the schema.
  </Step>
  <Step>
    Open a Record to see its detail page. The detail layout is generated from the same
    schema.
  </Step>
  <Step>
    Choose **Edit**, change a value, and save. If another user changed the Record first,
    the API rejects the stale write instead of overwriting it silently.
  </Step>
  <Step>
    Choose **Delete** when a Record should leave the live list. Deletes are soft, so the
    Record is removed from normal views without cascading through linked Records.
  </Step>
</Steps>

<Callout type="info">
Validation is server-authoritative. The UI helps you enter valid data, but the API is the
source of truth and returns a `422` with a JSON Pointer path when a write is invalid.
</Callout>
