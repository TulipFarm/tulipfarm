title: Test backup and restore
description: Verify a complete backup, isolated restore, recovery evidence, and access denial.
---

TulipFarm's recovery set includes PostgreSQL, encrypted blob data, the Soul Git repository, and
key-provider metadata. The reference posture is at most five minutes RPO and one hour RTO; record
the actual hardware and provider profile for every drill.

## Prepare a backup

Run the operator script with `DATABASE_URL`, `SOUL_PATH`, `BLOB_PATH`, and `KEY_METADATA_PATH` set:

```bash
ops/resilience/backup.sh /secure/backups/tulipfarm-2026-07-26
```

The destination must not already exist. The script records checksums and never calls the
development reset path.

## Verify and restore in isolation

Start with the non-destructive integrity preflight:

```bash
ops/resilience/drill.sh /secure/backups/tulipfarm-2026-07-26
```

Use an isolated disposable database for an executing drill. The restore script requires explicit
execute and confirmation tokens and refuses existing filesystem targets.

## Acceptance evidence

Compare PostgreSQL LSN, Soul head, blob digest, key-metadata digest, waiting Run count, ambiguous
effect count, and audit tail hash before and after restore. Resume one waiting Run, reconcile one
ambiguous effect, verify audit integrity, and complete one denied-access check. Record backup and
restore duration, database size, CPU, memory, storage, and provider.
