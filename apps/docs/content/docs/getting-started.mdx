You have a running instance and its URL. This guide takes you from there to a working
resource type with a record in it — about ten minutes, all of it in the browser.

<Callout type="info">
  No instance yet? [Install one](/docs/installation) — a single command, nothing to clone.
</Callout>

<Steps>

<Step>

### Create your admin account

Open your instance's URL. Because no admin exists yet, the app redirects to the setup
wizard at `/setup`. Work through the four steps:

1. **Admin account** — enter an email and password. This creates the first admin and logs
   you in.
2. **Business profile** — give your instance a name and optional description.
3. **LLM provider** — choose a provider (Anthropic, OpenAI, Azure OpenAI, or an
   OpenAI-compatible endpoint), enter the credentials, and pick a model. You can skip this
   and configure it later.
4. **Soul backup** — optionally point the soul at a git remote for backup. You can skip
   this and set it up in **Settings** later.

After step 4 the wizard redirects to the main workspace and the setup route locks — a
second browser visitor cannot create another admin through it.

<Callout type="warn">
  Until an admin exists, `/setup` is unauthenticated: on an internet-reachable instance,
  whoever arrives first claims it. Do this immediately after installing, or seed the admin
  from environment variables with [headless seeding](/docs/deploy/headless).
</Callout>

</Step>

<Step>

### Give the assistant a model

You build everything else by talking to the assistant, so it needs a model to run. If you
skipped step 3 of the wizard:

Open **Settings → Secrets**, add an API key for a provider (Anthropic, OpenAI, Azure, or
any OpenAI-compatible endpoint), then open **Settings → LLM** and assign a model to each
tier. The walkthrough is in
[Configure LLM providers](/docs/guides/configure-llm-providers).

</Step>

<Step>

### Build your first resource type — by asking

Open **Chat** and type what you want in plain language:

```prompt
Create a customer resource type with a name and an email.
```

The assistant confirms a couple of details and builds the type for you. There is no schema
to write and no restart — the new `customer` table is ready the moment it finishes. Open
**Resources** and you will see `customer` in the list.

This is the normal way to build in TulipFarm; see
[Building by chat](/docs/concepts/building) for the full picture.

</Step>

<Step>

### Create a record

Ask the assistant to add one:

```prompt
Add a customer named Ada Lovelace with email ada@example.com.
```

Or open **Resources → customer → New** and fill in the form by hand. Either way you now
have a running TulipFarm instance with a custom resource type and your first record.

</Step>

</Steps>
