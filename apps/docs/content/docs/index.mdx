TulipFarm is a control panel for your business that you run on your own computers. Inside it,
AI agents do real work: tracking customers, answering support tickets, chasing invoices,
reviewing code.

You do not configure TulipFarm by editing files or writing code. You describe what you want in
chat — "track our customers", "create a support agent" — and an agent builds it.

## The two halves of an instance

Every TulipFarm instance is made of two parts, and almost everything in these docs sits in one
or the other.

- **The soul** — the definitions. Your record shapes, agents, skills, routines, and connections
  live here as files in a git repository. When you ask an agent to build something, it writes
  to the soul, so the git history becomes your audit trail.
- **The runtime** — the working parts. The service and background workers that load the soul,
  store your data, index your knowledge, and run agent turns against the AI models you
  configured.

The soul is what your business *is*. The runtime is what your business *does*.
[Building by chat](/docs/using-tulipfarm/how-building-by-chat-works) is where the two meet.

## Install it now

One command, on any Linux or macOS machine with a terminal. It finds a container engine,
generates every password and key for you, starts everything, and prints the address to open:

```bash
curl -fsSL {{SITE_URL}}/install.sh | sudo bash
```

Windows, from PowerShell:

```powershell
irm {{SITE_URL}}/install.ps1 | iex
```

Open the printed address and create your admin account. That is the whole install.
[Full install instructions](/docs/self-hosting/install) cover what each step does and what to do
when one fails.

<Callout type="info">
  You never download the source code to run TulipFarm. Every path above pulls a ready-made,
  published image.
</Callout>
