Settled at charting — the premises every ticket inherits

  1. The harness is under test. Two models are a control, not competitors. A change that lifts both is real; one that lifts a single vendor is overfitting.
  2. Claude Sonnet + a GPT model. Different vendors deliberately — a same-vendor pair shares failure modes and decorrelates far less.
  3. Two tiers. L2 turn-level spine, L3 journey tier on top. Reaffirmed after research priced L3 at 3–6 engineer-days.
  4. Advisory, not a gate. A gate built before the noise floor is measured is a gate that gets bypassed.
  5. Deterministic Expectations first. Judge only for prose, and the judge must be a third vendor pinned to an exact version. (Called "assertions" at charting — renamed in ticket 04; Memory owns that word.)
  6. Frozen eval-only Soul fixture. Never the shipped default — two moving parts make a score change unattributable.
  7. GitHub Actions dispatch + protected Environment. Write access is already required on this public repo; reviewers gate the spend.
  8. ~$5 per full run, both tiers, both models, every run.
  9. The old src/evals/ gets deleted. Zero call sites, and a different product surface. (Done — ticket 02.)
  10. Local CLI and CI share one runner. An eval with a slow feedback loop is an eval you stop using.

Findings that bit an assumption

The L3 seam existed — and was unreachable

The spec checked that createChatExecutor already accepts an injected model, and stopped there. It does. But it lived in apps/worker, and the first dependency rule forbids one app importing another — while apps/eval must be an app, because packages may not import from apps/*. Neither half is negotiable, so L3 was simply unbuildable as specced.

The first measurement said extracting it meant 22 files, 3,528 lines, 8 dependencies — prohibitive. That measurement was wrong. Counting only imports that survive type erasure (dropping import type) gave 9 files, 1,507 lines, 3 dependencies: the heavy modules were referenced only as types. A sixth of its apparent size. packages/turn-executor now exists; worker's 408 tests still pass. Reuse that measurement before calling any extraction too big.

Two names were already taken, and one bug failed green

The spec called a deterministic check an Assertion. The glossary already binds that word to one durable Memory statement, and one term may not name two concepts — so it is now an Expectation, which reads better anyway since the field was already expect.

Worse: an Eval Case with an empty expect scored as a pass, because [].every(...) is true. It would have cleared a release gate having checked nothing. Now rejected at load, counted against the exit code, and named Vacuous in the glossary. This is the framework's worst failure mode precisely because it fails green — the spec never anticipated it.

The Tool loop does not see Context assembly — the spec was wrong

AgentLoopInput carries messages that are already assembled, plus digests. Context assembly and guardrail composition are separate functions sitting above the loop. Attaching the eval only at the loop would have measured the Tool loop against hand-written prompts and would never have caught a Context-assembly regression — one of the main things this framework exists to catch. Fix: the L2 runner calls the real assembler first. Cheap, because the assembler is pure and in the same package, but it decides what an Eval Case must carry, so it went into ticket 03 rather than being bolted on later.

There is no temperature knob

ModelInvocationRequest exposes no temperature, top-p or seed anywhere on the ModelPort path. You cannot run at temperature 0 today. That makes your noise floor the harness's true unmitigated variance — honest, but likely worse than a mature eval reports. Ticket 16 is deliberately blocked behind the measurement so nobody adds product surface on a hunch.

The judge is nearly free and needs no new code

Gemini ships an OpenAI-compatible endpoint, so gemini-2.5-flash-lite drops into the existing openai-compatible provider as pure config — about 1% of the $5 budget. One catch: provider.ts never passes supportsStructuredOutputs, so the judge needs its own model instantiation or you will be parsing prose out of your scorer. Ticket 13.

Prompt caching will not save you money

decidePromptCache is never called on the AgentLoop seam. The charting hope that caching would cut the L2 bill is not available for free. Moved to fog, to be priced once ticket 05 reports real per-case cost.

L3 is cheaper in infra and dearer in labour than expected

No Docker Postgres — makeMigratedPglite() already runs the full migration set in-process — and pg-boss is not on the single-turn path. But createChatExecutor needs ~12 ports with only 2 reusable fakes, Soul writes need a real git repo, and Expectations span three stores. The researcher recommended L2-only; you kept L3 knowingly, and it was split across tickets 09 and 10 because it does not fit one sitting.

There are no API keys — and that changes the shape of the thing

The spec named anthropic and openai as the two vendors and built a dollar spend ceiling around them. Ticket 05 discovered the operator holds neither key, and that what this deployment actually reaches a model with is two vendor CLI subscription seats — which is exactly what was asked for at the outset, and which packages/llm/src/cli/ has driven all along.

Three consequences, none cosmetic. (1) priceCall classifies both as subscription — correctly, a seat has a genuine zero marginal cost — so the dollar ceiling can never fire. A token ceiling had to be added, because tokens are what the vendor meters. (2) sonnet and gpt-5.6-luna are aliases. No dated id exists for a seat, so the promise that a Sweep isolates harness change from model change is weaker than the spec claims. The Scorecard now prints that caveat rather than hiding it. (3) Ticket 01 is not merely deferred, it is wrong as written.

The AI SDK was retrying behind the harness's back

A Sweep exists to tell a harness change from vendor noise. But streamText retries transient failures silently, so a run whose vendor was throttled throughout scored identically to a clean one — the exact confound the framework was built to remove, sitting one layer below where anyone was looking. It now passes maxRetries: 0 and owns the policy itself, so a retry is counted and the failed attempt's tokens are still charged. A throttled call was billed for the prompt it submitted.

Credentials — what you actually need, and when

This section was wrong until ticket 05. It assumed three API keys. You hold none, and the repo has driven subscription CLI seats all along (packages/llm/src/cli/). Everything below is rewritten for that.
Now — to run a real sweep locally
Claude Code seat. Run claude setup-token and export the result as CLAUDE_CODE_OAUTH_TOKEN. The runtime jails HOME when it shells out, so your existing ~/.claude login is not visible to it — the token is required even though you are already signed in.
Before ticket 07
Codex seat. Run codex login, then export the file's contents: export CODEX_AUTH_JSON="$(cat ~/.codex/auth.json)". You are not logged in locally today. Same jail applies.
Before ticket 13
Judge. Still an open question. The judge must be a third vendor, and neither seat above qualifies for both subject models. This may be the one place an API key is genuinely unavoidable — but not until the corpus holds judge-scored prose, which is a long way off.
Ticket 01 — re-decide
CI cannot hold a seat. A personal OAuth token is one person's credential. Putting it in a public repository's secret store is a security exposure and against the spirit of the vendor's terms. So a release Sweep either runs on a maintainer's own machine and uploads its Scorecard as a release artifact, or the org buys API keys. Only you can make this call.
A seat costs $0 per call and is still finite. The dollar ceiling built in ticket 05 can never trip on a subscription — priceCall correctly reports subscription, not a price. What a runaway sweep burns is your quota, so always pass --max-tokens. That is the ceiling that binds.

Tickets — 16 vertical slices

Each slice cuts a complete path and is verifiable on its own. Ticket 03 was the tracer bullet and it has landed: the whole spine — CLI, assembler, real Tool loop, scorer, scorecard — runs today against a scripted model, free and with no credential. Everything after it widens that bullet rather than replacing it. Faded cards are done; the red card is the one blocker that was not in the plan.

Not yet specified — the fog

  • The exact scorecard layout. What a maintainer reads to make a release call. Shape settles inside ticket 11, once deltas exist to display.
  • Turning the advisory report into a gate, and at what threshold. Blocked on a real variance number from ticket 14. A gate whose threshold sits inside the noise band trains you to ignore it.
  • Deprecation policy for the two subject models. The judge's is settled; the subjects' is harder — a retirement invalidates the baseline in a way no re-scoring repairs.
  • Recovering the prompt-caching saving. Not free on this path. Worth reaching for only if ticket 05 says the bill hurts.
  • Principal credential fallback as a silent confound. principalModel() falls back to the shared deployment credential without surfacing it. Unclear whether sweeps use a principal at all — ticket 05 must fail loudly either way.

Out of scope — ruled out, will not graduate

  • Online / production evals. Explicitly excluded; this effort is offline only.
  • Agent-publication gating. The deleted module's concern — an operator evaluating their own Agent before publishing. Different surface, different user, fresh effort if wanted.
  • Model leaderboard. The two models are a control, not candidates. Ranking them is a different question with a different corpus.
