## Changes

Created the private `@tulipfarm/memory-core` workspace package. Its three
contract modules are byte-for-byte copies of the M0 implementations:

| Original module                                  | Core module                                    |
| ------------------------------------------------ | ---------------------------------------------- |
| `knowledge/src/contracts.ts`                     | `memory-core/src/contracts/knowledge.ts`       |
| `conversations/src/personal-memory-contracts.ts` | `memory-core/src/contracts/personal-memory.ts` |
| `conversations/src/compaction-contracts.ts`      | `memory-core/src/contracts/compaction.ts`      |

The old modules re-export their respective core subpaths. No consumer import,
schema definition, runtime policy, permission check, ranking function, model,
dimension, or existing test changed. New host tests check identical export
names and strict object identity through the original paths.

The core has one runtime dependency: the existing `zod` version. The shared
TypeScript configuration and Node types are development-only dependencies.
The initial standalone build lacked `TextEncoder`'s ambient type; compiler
file-list inspection confirmed Node declarations were not loaded. Explicit
`types: ["node"]` supplies those types without a runtime import or code change.

Added `tulipfarm/memory-core-boundary` to the existing Oxlint plugin and enabled
it for core source and tests. It rejects host/Postgres/Temporal imports,
re-exports, type imports, dynamic imports, CommonJS loading, relative escapes,
and environment access. Static Node APIs and internal relative imports remain
valid. Computed module paths that cannot be checked statically are rejected.
This is an architecture fence, not an untrusted-code sandbox.

The new tooling test runs the actual root lint configuration against positive
and negative fixtures and verifies host adapters remain unrestricted. Existing
CI already runs `pnpm lint`; no workflow change is needed.
