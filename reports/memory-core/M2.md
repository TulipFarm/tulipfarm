# M2: Parser and chunking

Status: complete. All 222 integration entry points match the refined M0
baseline. Previous milestone: `fbb1642`.

## Changes

Moved all 14 `knowledge/src/internal/parser/*.ts` implementations into
`memory-core/src/parser/`, including normalization, token measurement,
chunking, document admission checks, conversion, isolated process management,
and the worker entry point. Moved the public facade to `memory-core/src/parser.ts`.
All original public and private Knowledge paths remain forwarding modules.
The old worker path imports the moved worker for its original side effect.

The five parser imports of host `internal/contracts.ts` now import a pure
core `document-contracts.ts`. It contains the exact original `knowledgeLimits`
object and `chunkSchema` definition. Knowledge imports and re-exports those
same objects; the rest of the host module and its access-aware contracts stay
in place. The core root entry remains browser-safe and does not import the
Node parser or tokenizer.

Conversations' two source imports now use `@tulipfarm/memory-core/parser`.
Its Knowledge dependency is development-only because the existing maintenance
integration test still composes the host Knowledge service. There is no
Conversations-to-Knowledge runtime source import or production dependency.

Core owns the existing pinned AnyDoc, tokenizer, PDF, and Zod runtime
dependencies. Knowledge retains the tokenizer for its embedding provider,
and AnyDoc/PDF as development dependencies for its existing census and
semantic-fidelity fixtures. Core's moved fixtures use the existing JSZip
version as a development dependency. No external package version or resolved
snapshot changed; the lockfile changes only workspace importer ownership.

Moved three parser suites and their 204 tests into core:
`parser.test.mjs`, `parser-completeness.test.mjs`, and
`parser-semantic-admission.test.mjs`. Four shared fixture implementations
also moved into core, with forwarding exports at all original host fixture
paths. Core fixtures import no host tests or packages.

The parser-process suite stays in Knowledge. It deliberately writes ambient
environment variables to verify they cannot reach the child process, which
the core architecture fence forbids in core tests. Its old module imports
now exercise the exact core process implementation through re-exports.
The concurrency counter, sanitized child environment, resource limits,
process-group termination, admission grammar, profile, failure classes,
and all existing assertions remain unchanged.

Two new Knowledge compatibility tests verify public export identities,
the 13 importable private modules, and shared document-contract identities.
The worker module is intentionally not imported by the identity test because
it reads stdin on import; the real parser suites exercise it through the
unchanged isolated-process path.

## Deviations and continuation

The pure shared document-contract seam is required because the original
host contracts module also imports access-aware schemas; moving it wholesale
would violate the core boundary. Keeping environment-probing tests in the
host preserves both their assertions and the core fence.

No remote action or amendment of prior commits. M2 is ready for its new
local milestone commit. The owned Compose project remains available for
M3's required comparison and will be removed when no longer needed.
