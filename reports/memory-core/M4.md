# M4: Authorization and eligibility ports

Status: **complete; paused for required security review before M5**.
Previous milestone: `6159003`. No security review was run by this worker.

## Changes and authorization surface

Added the host-independent `Authorizer` and `EligibilityFilter` ports.
An authorizer binds its host transaction and principal when constructed;
its core interface accepts typed check inputs and returns an explicit
`AccessDecision`. No database transaction or host package is imported
into core. `requireAccess` consumes the decision, retains the exact host
denial object, and fails closed on a missing or malformed decision.
Infrastructure and validation errors are not converted into permissions,
empty results, or successful decisions.

The concrete adapter is in `knowledge/src/authorization/authorizer.ts`.
It owns source state/ownership/provider-reader checks, original-file
readability plus digest/size checks, protected source closure and MCP
derivation checks, current membership, tenant/revision/publication/epoch
bindings, conversation authority, current task-run generation/requester
binding, external and stored access proofs, embedding ownership/provider
checks, and query-dispatch scope cancellation/expiry/SQL eligibility.
Admission helpers retain authorization-lock, principal-resolution, and
current-member order. Host error classes and identity are unchanged.
The live-document decision only preserves the existing missing/tombstone
guard; it is not a standalone grant to read a source. Source ownership,
dependencies, proof checks, and final rechecks still run before evidence
is returned.

The bound transaction hooks for retained knowledge sources moved into
that adapter. They retain current membership and task checks, the exact
KnowledgeError-to-AccessDenied translation, and the existing audience
checking contract. The dependency traversal still checks each original
file but clears nested sources when entering the already expanded closure;
the recursion/cycle guard did not change. Evidence reads and final
retrieval proof-set rechecks stay at the original call points.

Conversation and external authority implementations moved unchanged into
`knowledge/src/authorization/{conversation,external}.ts`; old paths
forward all original symbols. `requireTaskRun` still exports from Store.
Core-facing domain modules no longer directly import `@tulipfarm/access`
or `@tulipfarm/files`. A host-only contracts bridge retains existing
schemas, types, and error classes; it exports no granting functions.
Actual checks use the adapter, not the bridge.

Eligibility SQL now lives in the host `EligibilityFilter` adapter.
It still returns the existing storage-side predicate rather than filtering
all candidates in application code. Search's selected-reader checks keep
Slack/GitHub/Atlassian query order and disabled-provider short circuiting.
Embedding dispatch intentionally uses configured providers, not Search's
selected-reader flags. Discovery membership/conversation-maintenance
joins and conversation embedding-requester selection moved to
`authorization/embedding-candidates.ts`; their existing Zod parsing and
position in the work flow are unchanged.

Core owns the existing pure proof-age and current-time comparisons.
The host maps `membershipCheckedAt` to `principalCheckedAt`, retaining
both check timestamps, the exact five-minute upper bound, strict expiry,
and future-check rejection. Invalid Date objects fail closed in the
standalone core helper; the existing host Zod schema already rejects
them. No new clock read, proof lifetime, expiry recheck, epoch increment,
SQL predicate, or host error was added to a valid existing path.
Per-read `clock_timestamp()` checks remain in the same queries.

## Deliberate staging

M4 extracts the actual access checks and SQL eligibility into host adapters.
Store, Search, and Embeddings still own their existing transaction/repository
composition until M5; claiming those whole modules are already core would
be incorrect. Their existing transaction/schema and actor/dependency types
remain host composition details, while the new core ports contain none.
The Authorizer check map is generic so the host can retain its exact
request/result types without importing them into core or using casts.
M5 will separate repository/transaction logic, not move host permission
computation into core.

### Callback receiver correction

Inspection found one refactor error before the milestone was committed:
calling `external.requireExternalSource(...)` and
`external.requireExternalProof(...)` gives those callbacks the adapter
object as `this`, whereas Store called both as bare functions.
A new test using ordinary functions reproduced the difference;
`M4-callback-red.tap` retains that failing new assertion.
The adapter now destructures and calls both functions exactly as Store did.
The same new test passes, together with the other 22 focused checks.
No original test or host callback implementation changed.
