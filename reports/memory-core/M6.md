# M6: personal memory

Baseline: `737e0d3`, including the approved M5 UUID compatibility fix.
Implementation and verification are complete. All 222 integration entry points
match the agreed M0 comparison rules. No new comparison exception was added.

## What moved

`memory-core/memory/personal-memory` owns document reads, Unicode/whitespace
validation, revision compare-and-swap, automatic versus manual replacement,
pending-step cleanup, and change notification ordering.
`memory-core/memory/reconciliation` owns the existing preference prompt,
literal-requester-evidence parser, and complete reconciliation state machine.
`memory-core/memory/transcript` owns the existing Unicode-safe byte splitting
and transcript chunking helpers.

The new `MemoryRepository`, `MemoryReconciliationRepository`, and
`TranscriptSource` ports have named, typed operations. Their Postgres adapters
use explicit schema/table-prefix configuration and bound values. Core receives
opaque transaction contexts, explicit authorization decisions, `EgressPolicy`,
the existing `Summarizer`, and a host change callback. It imports no Access,
Files, Postgres, ambient environment, or other TulipFarm package.

The existing Conversations paths forward their original exports. Conversations
still owns transaction setup/version compatibility, locks, human resolution,
current membership, MCP egress restrictions, maintenance/lease fences, Bud
preference cleanup, and recommendation invalidation. A replacement with
identical text still increments the revision and clears manual pending steps,
but does not emit a recommendation change. Deletion retains its revision;
stale writes cannot recreate it.

## Equivalence proof

`M6-move-proof.json` compares against `737e0d3`:

- All 18 moved query occurrences map to 16 named operations with identical SQL
  and bound-value expressions in their original order.
- The complete read, replace, and reconciliation bodies are AST-equivalent
  after explicit port substitutions; their branches and validation order match.
- Prompt, evidence schemas/parser, and transcript helpers are equivalent.
- Host service validation, transactions, locks, human resolution, and Bud
  cleanup are unchanged. Recommendation payload and random-ID generation match.
- Access, Files, apps, Knowledge, maintenance fencing, migrations, existing
  tests, frozen M0 artifacts, and external dependency resolutions are unchanged.

No behavior, schema, API response, permission, ranking, model/dimension,
or Temporal change is intended. In-memory fixtures exercise the same core
interface with Symbol transaction contexts. Existing personal-memory and
maintenance Postgres integration tests remain unchanged and use the new
adapters through host composition.

The reconciliation store is a separate named port rather than adding job
progress and replay operations to the personal-document repository. This keeps
document callers independent of maintenance storage while preserving the
existing fenced transaction callback. The shared transcript-slicing helper is
moved once; unrelated host compaction code imports the same implementation.
