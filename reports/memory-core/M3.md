# M3: Provider and runtime ports

Status: complete. Previous milestone: `667a34f`.

## Changes

Promoted the embedding provider to `memory-core/src/embeddings/provider.ts`.
The provider takes an explicit embedding profile instead of importing host
configuration. Input validation, verbatim token measurement and hashing,
request construction, timeout and cancellation handling, indexed vector
validation, usage accounting, request-ID filtering, and error results are
unchanged. `ports/embedding-provider.ts` owns the generic provider types.
All previous Knowledge names and paths remain available through a forwarding
module and host adapter.

TulipFarm's adapter still supplies the complete frozen embedding profile:
`text-embedding-3-large`, 1,536 dimensions, the same preparation, limits,
quota, and pricing. The entire original profile object, not a reduced core
projection, continues to be persisted and compared in embedding jobs.
Neither configuration parsing nor the request-model/response-model distinction
changed.

Promoted the compactor interface to the core `Summarizer` port. The existing
`ConversationCompactor` name is a type alias with its original transaction
and fence types. Its worker implementation, prompts, routing, measurement,
purpose, and metering remain unchanged. Generic context and fence parameters
preserve the existing interface without importing host authorization or
worker types into core. The original type exports remain available.
Moving the personal-memory and reconciliation implementations is still M6.

Added `Clock`, `Telemetry`, `FeatureFlags`, and `UsageMeter` ports. The host
adapters live in `knowledge/src/host-ports.ts`; Knowledge's domain modules
no longer import config, observability, or extensions directly. Embedding
pricing, credit reservation, dispatch marking, outcome recording, and usage
reporting use the injected meter at the same transaction and dispatch points.
Its default methods are the exact existing functions, including their error
and reporting behavior. No SQL or credit boundary moved.

Search, retrieval, model-facing tools, embeddings, conversation publication,
and provider engines accept an explicit clock. Polling and retry sleeps use
that clock; existing database `clock_timestamp()` checks remain unchanged.
Tools pass their clock and deadline budget to their nested retrieval module.
The host defaults still use wall time and the existing call timeout.
Provider `now` overrides and defaults' `enabled`/`now` overrides retain
precedence over the new ports.

Automatic-source gating uses the feature flag port with the same fixed flag
and exact user-ID/workspace-ID mapping. GitHub import events use the telemetry
port with the original stage, outcome, reason, and diagnostics.
