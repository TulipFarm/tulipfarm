## Reference implementation

`memory-core/adapters/in-memory` implements every operation of
`MemoryRepository`, `MemoryReconciliationRepository`, and `TranscriptSource`,
with a shared `TenantRuntime`. It stores real documents, revisions, metadata,
maintenance progress, pending steps, conversation ownership, message parts,
and accepted coverage. There is no generic successful-query fallback.

Each tenant has an independent transaction queue. A transaction works on a
snapshot and commits only after its callback succeeds within its deadline.
Failures roll back document writes, pending-step removal, and progress
together. Contexts cannot be forged, used after their callback, or borrowed
from another adapter instance. Same-tenant re-entry fails explicitly instead
of deadlocking; unrelated tenants can progress independently. The clock is
injected, and no host environment or authorization is inferred.

Manual versus automatic writes preserve their original timestamp and
watermark behavior. Timestamp comparisons retain Postgres microsecond
precision; the reference rejects unsupported higher precision explicitly.
Transcript selection excludes other requesters, nonhuman/internal messages,
uncovered turns, completed earlier-generation coverage, and messages at or
before the manual edit. Parts and messages keep their respective ordinal
and sequence ordering. Returned records and seeded fixtures are copied.

The set covers the complete mutable personal-memory module, not a simulated
Postgres query engine. Existing document, search, and embedding unit fixtures
remain unchanged; their real Postgres/Temporal integration tests remain the
reference for their SQL and provider-specific behavior. No partial fake is
installed into production composition.

## Shared conformance

`@tulipfarm/memory-core/testing/memory-conformance` exports one suite for each
of the three repository/transcript ports. The same 24 cases run against the
reference adapters and the actual `memory-postgres` factories. They cover
missing rows, first-writer and revision conflicts, unchanged/deleted content,
manual metadata, monotonic watermarks including microseconds, scoped step
cleanup, progress transitions, requester evidence filtering, and isolation
of returned records.

The reusable harness lives in `testing/`, rather than the local `test/`
directory, because dependent cached test tasks need its changes to affect
the core build hash. A tooling regression checks the real package export and
both effective Turbo build/test inputs. Local uncompiled tests remain
excluded from compiler build inputs as established in M7.

The Postgres harness uses disposable, uniquely named schemas on the same
owned Compose cluster and the real adapters with a nondefault table prefix.
Its minimal tables exercise storage-port behavior without inventing host
authorization or replacing the unchanged full-workspace integration tests.
Each schema is dropped and its connection closed by test cleanup.
Application migrations are untouched.

The initial development run exposed six overconstrained new assertions:
Postgres returns its driver's `Result` instance, not a plain object.
The new suite now compares exactly the declared `rows` and `rowCount`
fields, without asserting anything about driver-private metadata. No
production adapter or existing test changed. The initial receipt is retained.

Additional pure core tests exercise tenant isolation, rollback, deadlines,
context lifetime, independent queues, nested-transaction rejection, input
copies, real personal-memory competing writes and invalidation rollback,
and complete quoted-evidence reconciliation across separate transactions.
