# Phase 14 verification

Phase 14 release evidence is generated by running commands; checked-in pass/fail constants are not
accepted. `verifyPhase14Record` binds a successful record to the exact Git commit, Git tree, and
API, Worker, and Integration Worker component digests selected for cutover.

Create a trusted, operator-controlled local JSON command plan with this shape. `runId` may contain
letters, numbers, dots, underscores, and hyphens:

```json
{
  "runId": "phase14-2026-07-26-01",
  "components": {
    "api": "sha256:<64 lowercase hexadecimal characters>",
    "worker": "sha256:<64 lowercase hexadecimal characters>",
    "integrationWorker": "sha256:<64 lowercase hexadecimal characters>"
  },
  "commands": [
    { "id": "test", "command": ["pnpm", "test"] },
    { "id": "lint", "command": ["pnpm", "lint"] },
    { "id": "typecheck", "command": ["pnpm", "typecheck"] },
    { "id": "build", "command": ["pnpm", "build"] },
    { "id": "compose", "command": ["<compose acceptance executable>"] },
    { "id": "chat", "command": ["<Chat acceptance executable>"] },
    { "id": "webhook", "command": ["<webhook acceptance executable>"] },
    { "id": "schedule", "command": ["<schedule acceptance executable>"] },
    { "id": "effect", "command": ["<effect/reconciliation acceptance executable>"] },
    { "id": "acl-deny", "command": ["<denied-access acceptance executable>"] },
    { "id": "restore", "command": ["<isolated restore acceptance executable>"] }
  ]
}
```

Run it from the repository root:

```bash
pnpm verify:phase14 -- /absolute/path/to/plan.json
```

Commands execute directly without an implicit shell, in the required order. Exit status determines
pass/fail. Combined stdout/stderr is written to mode-`0600` logs and hashed into the manifest.
Evidence defaults to `.phase14-evidence/<runId>/`, which is ignored by Git.
Acceptance commands must emit redacted output: never print Secrets, credentials, or protected
payloads into verification evidence.

The operator must independently resolve the three component digests from the deployment plan.
The command plan must also be independently approved; a command such as `/usr/bin/true` is not an
acceptable substitute for an acceptance check. Verification consumers must call
`verifyPhase14Record` with the expected commands, component digests, and repository revision.
Missing, stale, reordered, substituted, malformed, mismatched, or failed evidence rejects the
release.
